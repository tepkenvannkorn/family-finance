Architecture

Modular MVC. Each module under app/Modules/<Name> is self-contained: Controllers, Views, its own routes.php, and (where needed) Requests, Services, Repositories, and Policies. The front controller (public/index.php) auto-loads every module's routes.php via glob() — adding or removing a module is adding or removing that one file.

Request → public/index.php
        → Session::start() + remember-me cookie resume
        → maintenance-mode gate
        → Router::dispatch()
            → middleware pipeline (Auth, Csrf, Permission, FeatureFlag)
            → Controller
                → Request (validation) / Policy (authorization)
                → Model or Repository (data)
                → Service (business logic, e.g. CurrencyConverter)
            → View::render() (auto-escaped output)
flowchart LR A[Router] --> B[Middleware pipeline] B --> C[Controller] C --> D[Request/Policy] C --> E[Model / Repository] C --> F[Service] C --> G[View]

Why no full framework

This is a private, single-household application. A hand-rolled router/DI-free core keeps the entire request lifecycle auditable in a few small files — appropriate for the security-sensitive, low-traffic nature of the app — rather than pulling in a large framework's surface area.
