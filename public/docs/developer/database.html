Database Schema

See /database/migrations for the authoritative, versioned schema (one file per table). Summary ERD:

erDiagram ROLES ||--o{ USERS : "has many" ROLES ||--o{ ROLE_PERMISSIONS : "has many" PERMISSIONS ||--o{ ROLE_PERMISSIONS : "has many" USERS ||--o{ TRANSACTIONS : "creates" USERS ||--o{ DASHBOARD_PREFERENCES : "personalizes" USERS ||--o{ AUDIT_LOGS : "performs" CATEGORIES ||--o{ TRANSACTIONS : "classifies" TRANSACTIONS ||--o{ ATTACHMENTS : "has"

Notable design choices

  • exchange_rates is append-only — every change is a new timestamped row, so historical reports use the rate that was current at the time.
  • transactions.deleted_at — soft delete; recoverable by an admin (schema-level; no restore UI yet).
  • settings is a grouped key/value store, typed via a type column, so new settings never require a migration.
  • totp_secret and recurring_rule columns exist but are unused today — provisioned ahead of the 2FA / recurring-transactions features listed as future work.
